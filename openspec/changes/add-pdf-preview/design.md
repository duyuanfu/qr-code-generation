## Context

目前移动端扫码落地页中，图片支持大图画廊灯箱，视频支持流媒体播放，而文件类型统一渲染为单一的“下载”操作。但 PDF 文件在商业宣传、合同展示、菜单价目表、会议日程等场景下，用户最强烈的诉求是“扫码即可在手机上直接阅读翻页”，而不是强制将文件下载到手机本地存储再通过第三方应用打开。

## Goals / Non-Goals

**Goals:**
- 在移动端扫码落地页（`/q/[shortId]`）的文件列表中，自动识别 `.pdf` 或 `application/pdf` 格式。
- 为 PDF 文件提供【在线预览】（Preview）与【下载原件】（Download）双操作入口。
- 实现全屏沉浸式 PDF 阅读器弹窗（Modal / Fullscreen Drawer），支持移动端手势双指缩放、翻页及退出。
- 在制作端右侧的 iPhone 模拟器视图中，同步支持查看 PDF 在线预览效果。
- 零额外体积包依赖：优先采用高效安全的现代浏览器原生 PDF 渲染管线与内联沙盒视窗（`iframe`/`object`）及 Google Docs / PDF.js 降级适配。

**Non-Goals:**
- 不做服务端 PDF 转图片切片集群（避免消耗服务器算力与额外磁盘）。
- 不对 Word (.docx)、Excel 等 Office 二进制格式做在线排版转换（此类文件依然保持极速下载模式）。

## Decisions

### 1. 纯客户端高保真 PDF 渲染架构
- **决定**：使用纯前端自适应方案。在支持原生 PDF 视窗的 iOS Safari、iPadOS、现代 Android 浏览器中，利用响应式全屏内嵌层进行直接流式高保真渲染；针对特定受限环境（如部分安卓微信内核），提供一键全屏直开与下载兜底。
- **理由**：不增加额外 Node.js 包体积，不占用服务器 CPU/内存转码资源，毫秒级即点即开。

### 2. 交互入口：双按钮并列卡片
- **决定**：将原本单一的 `[下载]` 按钮拆解：针对普通文件保持 `[下载]`，针对 PDF 文件展示 `[在线预览]` (蓝底主按钮) + `[下载]` (浅色次按钮)。

### 3. 全屏沉浸式阅读器 UI
- **决定**：点击预览后弹出带顶部操作栏的全屏覆盖层，顶部展示文件名、页内快速关闭按钮与原件下载快捷键，保障在窄屏手机上的阅读视野最大化。

## Risks / Trade-offs

- **[Risk] 部分老旧安卓系统或微信内核对 iframe 直接加载 PDF 有阻断** → 增加“如无法内嵌浏览，点击[在新窗口打开]或[直接下载]”的贴心容错提示，确保 100% 可访问。
